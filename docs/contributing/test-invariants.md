# Test-suite invariants

What each block of the test suite pins down, and which load-bearing rule
would break if an assertion were weakened. Relocated verbatim from CLAUDE.md.
Per-PR implementation history lives in `docs/changelog/`.

## The suite
- Test suite: `source .venv/bin/activate && python3 -m pytest tests/ -v`
- 2241 tests covering all computation functions, with hand-computed expected values from IRS worksheets, + FL type-none state module (template/freshness, sales-tax input, harvest banner, capability note, property calendar, registrations). **Per-PR / per-Codex-round implementation history lives in `docs/changelog/` (one file per epic I–P + `pre-epic.md`); the load-bearing invariants each block must preserve are inventoried below.** When adding a test, update the count above; when changing an assertion, update its worksheet comment.
  - **A dependency pin nothing imports is not pinned (`test_pdf_toolchain.py`):** no other test imports `reportlab` or `pdfplumber`, so a bump used to reach `main` on a green CI that had proved only that pip could RESOLVE it — `generate_tax_pdf.py` is an untracked runtime artifact CI cannot see, and pdfplumber is imported lazily inside `parse_utils` where nothing reached it. Surfaced by the reportlab 4.5.1 -> 5.0.0 review: the whole release delta is one INVERTED DEFAULT (`trustedHosts=None` flipped from trust-all to trust-none), a change no signature diff or type checker can see. The build test renders the generator's full flowable + style + onPage-canvas surface; the round-trip test reads that PDF back through `extract_pdf_text` / `extract_tables` / `pdf_page_count`, so the two pins are pinned against EACH OTHER and no binary fixture is committed. Mutation-verified PER TEST rather than in aggregate, because the split is load-bearing: the build test fails on a removed/renamed reportlab symbol and on broken pagination, asserting reportlab's own `doc.page` and NOT a byte-size floor — the full document is ~2.2 KB and a PDF holding one character is ~1.4 KB, so any threshold admitting the first admits the second, which is a content check in appearance only. Silently-lost CONTENT is caught by the round-trip test alone, since an empty story still renders a well-formed two-page PDF. Neither catches a renamed TableStyle command, which reportlab ignores in silence — that stays a manual /tax-generate check. The third test walks the generator's imports with `ast` — BOTH statement forms, because a guard blind to plain `import reportlab.x` misses exactly how the graphics/renderPDF modules are conventionally imported, and the non-empty sanity check cannot catch that since the other lines keep the set populated. It fails unless `_build_reference_pdf` both IMPORTS and REFERENCES each one. The covered set is DERIVED from that function, never a hand-maintained list: a list makes appending a name the cheapest way to turn the guard green, silencing the alarm while creating the exact untested surface it exists to prevent — and importing without using is the same bypass one step quieter, which is why usage is checked too. Both bypasses are mutation-verified to fail, and a genuinely-updated mirror is verified to pass so the guard cannot cry wolf. It SKIPS on a fresh clone and in CI by design, firing only where the generator is actually edited (so CI reports 2240 passed + 1 skipped, not 2241 passed).
  - **A freshness gate must not fire on correct data (`test_tax_law_fetcher.py::TestScalarByDesignThresholds`):** `_EXPECT_STRUCTURED` matches on the KEY NAME, and `threshold` is a per-filing-status dict nearly everywhere it appears. CA's mental-health services surcharge is the exception — Prop 63 / R&TC §17043 set a flat $1,000,000 threshold and never indexed it, so `create_state_template` hardcodes a bare int. The key-name rule flagged the toolkit's OWN canonical CA template, so **every California return reported INCOMPLETE at `/tax-compute` Step 0.5 forever** — the sdi_wage_limit / underpayment_rates / phaseout_rate nag a fourth time, on the flagship state. This one is worse than a nag: Step 0.5 says INCOMPLETE plus no live web means STOP, so a gate that fires on correct data teaches the agent to reason its way PAST the freshness gate. Observed end to end in a naive-agent probe — the agent hit the false positive, correctly diagnosed it, then reclassified the cache FRESH and computed a full return on placeholder brackets. The exemption is keyed by exact PATH, never by key name; the paired leak guard pins that a scalar `federal.niit.threshold` is still corruption, and a third pins that a NULL at the exempt path still flags — as a plain missing field, not a misleading "expected dict/list". The fourth is the one that holds the LINE rather than the instance: it walks every state template (CA/NY/NJ/FL/TX/WA) and fails if any of them provokes a SHAPE complaint about its own canonical data, so the fifth field of this kind fails at the point the template is added rather than reaching a taxpayer. Pinning individual paths is what let this recur four times.

  - **Commit-time PII content guard (`test_pii_content_scan.py`):** drives the real `scripts/pre-commit-pii-scan.sh` inside a throwaway git repo. Pins that a full SSN in an ADDED line blocks; that the masked `XXX-XX-` storage format and `.pii-allowlist` values (`000-00-0000`) do not; that `tests/fixtures/` IS content-scanned even though it is exempt from the filename scan (a real SSN in a synthetic fixture is the mistake being caught); that only added lines count, so editing elsewhere in a file with pre-existing content stays committable; that tax figures, form numbers and ISO dates do not false-positive (a scanner that cries wolf gets `--no-verify`'d as a reflex); and that **the block message never echoes the matched value** — reporting file + count only, since printing it would perform the disclosure the scan exists to prevent. The clean-diff case is load-bearing: under `set -euo pipefail` a non-matching `grep` fails the pipeline and aborts the script, which exits non-zero with no output and is indistinguishable from a legitimate block. **Four bypasses found in PR-#67 review are pinned individually:** the allowlist filters extracted MATCHES with `grep -vxFf`, not whole lines (a line carrying both `XXX-XX-6789` and a real SSN previously passed); `SECRET_PATTERN` admits hyphens inside project-scoped keys (`sk-proj-…`, `sk-ant-…`), which a `[A-Za-z0-9]{20,}` class truncates at the first hyphen; staged paths are read NUL-delimited so a non-ASCII filename is not silently skipped by BOTH scans (`--name-only` quotes it, and the quoted form matches neither the extension rules nor a pathspec); and a git-classified-binary blob is BLOCKED rather than treated as clean, because it emits no `+` lines (a UTF-16 file holding an SSN is the concrete case, and byte-level grep would not find it either). **CI calls this same script with a `<base>...<head>` range** — `test_ci_invokes_the_shared_script_rather_than_reimplementing_it` stops the old hand-mirrored copy in `ci.yml` from creeping back, which is how all four bypasses came to exist in two places at once. **Round 2 added seven more, each pinned:** range mode inspects EVERY COMMIT individually (a net `base...head` diff hides a secret a later commit deleted — the case CI exists for); bare-nine-digit and space-separated SSN forms are detected, with exactly-nine-digit token extraction so 8/10/14-digit identifiers do not false-positive; `github_pat_` fine-grained tokens and `gh[pousr]_` join the credential set; added lines are marked via `--output-indicator-new` so real content beginning `++ ` is not mistaken for a `+++` file header; the allowlist is read from the STAGED snapshot (`git show :.pii-allowlist`) so an unstaged local edit cannot widen it, with the staged complement pinned too; an unusable base ref BLOCKS instead of yielding an empty file list that reads as clean; and the runtime workspace directories are path-blocked, making the README's promise true — with `tests/fixtures/` precedence pinned, since real fixtures live under `tests/fixtures/projection/archive/2025/result.json` and would otherwise trip both the `archive/` path rule and the `result.json` filename rule. **Round 3 added four more, all one shape — the scan asked git for a subset of the change and the subset had a hole:** merge commits are scanned against their first parent, because a conflict resolution is content present in the merge and in NEITHER parent, so `--no-merges` dropped the only commit carrying it while both sides scanned clean (re-examining the merged-in branch's lines is redundant, not a new false-positive source — they were already scanned via their own commits); `.pii-allowlist` is resolved PER SCANNED COMMIT rather than once from the range head, so allowlisting a value in a later commit no longer retroactively exempts the commit that leaked it, whose history is still pushed; the AWS pattern admits `ASIA` STS temporary access-key IDs alongside `AKIA`, and adds a CONTEXTUAL `aws_secret_access_key` rule — the secret access key is 40 unremarkable base64 characters, so `test_bare_forty_char_token_does_not_false_positive` is the deliberate counterweight pinning that an unlabelled 40-char string (a SHA, a checksum) stays committable; and the diff status filter became the DENYLIST `--diff-filter=d` (everything but deletion) after the `ACMR` allowlist silently dropped typechange, letting a tracked symlink be replaced by a regular file that bypassed the filename rules and the content scan alike — both the content and the blocked-extension halves of that hole are pinned, and enumerating statuses is the mistake the denylist stops repeating. **Round 4 turned the lens on the EXEMPTIONS, which are the gate's own attack surface, and on the one piece of content the content scan can never see — the pathname.** The allowlist has no working-tree fallback at all: the old one was guarded by "only when the file is untracked", and staging a DELETION of the tracked `.pii-allowlist` satisfies that guard, so recreating it in the working tree with the sensitive literal exempted a value the committed snapshot never allowed (`_make_repo` therefore STAGES the allowlist, mirroring the real repository where it is tracked). `count_hits()` now runs the same patterns over the PATHNAME as over the added lines — `reports/<ssn>.txt` committed cleanly with entirely innocent contents, since the filename rules know only extensions and known names — and it runs BEFORE every exemption, because no exemption should cover an SSN in a filename. Every message that prints a path prints the `redact()`ed form, with `test_ordinary_pathnames_are_not_redacted` as the counterweight pinning that redaction does not mangle the ordinary case and stop the message naming its file. The `documents/.gitkeep` exemption covers the path rule ONLY: it used to `continue` before the content scan, so a `.gitkeep` edited to hold an SSN passed — both halves are pinned, since the exemption itself must survive (an empty `.gitkeep` is what makes `documents/` exist in a fresh clone). Outside the scanner, `TestRuntimeWorkspaceIgnored` pins that every runtime directory AGENTS.md calls gitignored actually is, in `.gitignore` AND in the installer's appended patterns — `archive/` was in neither, and `tax-archive` moves `documents/` and `reviews/` beneath it, out of reach of the root-scoped rules; `test_hooks_only_mode_fails_when_the_hooks_were_not_installed` pins that the security setup step cannot print success and exit 0 after warning that nothing was installed; and `test_fbar_trigger_covers_signature_authority` pins that a description's trigger is not NARROWER than the skill's own prerequisites — signature authority alone triggers FinCEN 114 Part IV, and the $10,000 aggregate is what the skill performs rather than a precondition for selecting it, so the circular trigger's failure mode was a missing filing rather than an error. **Round 5 hit the AWS rule from round 3 twice, and the second one is the load-bearing invariant:** the detector and the redactor were separate pattern lists, the AWS rule was added to the detector alone, and the scanner therefore blocked a path containing an AWS secret and then printed that secret in the block message — a rule that is detected but not redacted turns the gate into a disclosure channel, which is strictly worse than not having the rule. Both now consume ONE `PII_PATTERNS` array, and `test_every_detected_pattern_family_is_also_redacted` walks every family (SSN, AWS access-key ID, project-scoped API key, AWS secret access key) through the pathname route, where the value is guaranteed to reach the message. The other half: the `{1,4}` separator bound could not span YAML's aligned value columns, so a five-space gap carried the credential through untouched while the bare 40-character value deliberately matches nothing else — the separator is now `*`, which cannot overrun because the class excludes alphanumerics. The keyword is spelled in character classes rather than matched with `grep -i`, because `grep` and `sed` spell case-insensitivity differently and not portably; a pattern that is case-insensitive BY CONSTRUCTION behaves identically in both, and `test_aws_secret_key_name_is_matched_case_insensitively` is the regression guard on that construction. **Round 6 questioned a premise the first five rounds shared — that `git` returns what the script expects.** Local configuration changes the output format: `color.ui=always` wraps added lines in ANSI escapes so they no longer begin with the parser's marker, `diff.external` replaces the patch with a program's output, and a textconv driver rewrites the blob before diffing. Each one empties the added-lines set and the scan reports clean, so a developer's display preference silently disabled a security gate. Every `git diff` now passes `--no-color --no-ext-diff --no-textconv`, and all three configurations are pinned. `git rev-list`'s failure was invisible for a structural reason: a process substitution's exit status is not the `while` loop's, so `done < <(git rev-list ...) || die` never fired and an empty scope list exited 0 — CI passing having inspected nothing.
