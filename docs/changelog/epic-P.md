# Epic P — Florida state module (type-none regime, pilot)

Post-review freshness correction: `sales_tax.state_rate` now ships `None` and
is fetched at setup alongside `county_surtax_rate`; the earlier inline 6% value
was not governed by AGENTS.md's sole fixed-rate exception. The general DOR page
pins `state.FL`, and the county table pins `state.FL.county_surtax_rate`.

> Detailed per-PR / per-Codex-round implementation history distilled out of `CLAUDE.md` (item O1). The load-bearing invariants remain in `CLAUDE.md`; this file preserves the how-we-got-here narrative and the refuted-vs-fixed review record.

the Epic P Florida module (`feat/state-engine-florida`, re-baselined 2026-08-01 against origin/main — the stale local checkout the backlog doc was drafted against was 40 PRs behind; the state-support roadmap's Epic 0.3 central `state_registry.py` proposal was SUPERSEDED by the already-shipped `docs/contributing/state-module-playbook.md` enumerate-and-register pattern, so this PR delivers Epic 0.1/0.2 as a `type` discriminator without a registry, plus all of Epic 1) — the schema-level fix is `tax_law_fetcher.create_state_template` gaining a `type` field (`"graduated_income"` on CA/NY, `"none"` on the new FL block; the generic no-state-code fallback deliberately carries NO `type` key so untouched states' freshness behavior doesn't move) so `check_freshness`/`loss_harvest`/the skills can finally distinguish "this state has no income tax" from "state data was never fetched" — the FL template ships `no_income_tax: true`, a constitutional citation (Fla. Const. Art. VII §5) in `note`, and a `sales_tax: {state_rate: 0.06 (F.S. 212.05), county_surtax_rate: None}` block, DELIBERATELY omitting `brackets`/`standard_deduction` keys (the freshness walker flags every empty list, so a field the design never fetches would nag INCOMPLETE forever — both `type` and `no_income_tax` were added to `check_freshness`'s `_SKIP_KEYS`); Florida's DOR is `floridarevenue.com`, a `.com` not a `.gov`, so it was added to the `_AUTHORITATIVE_NONGOV_DOMAINS` source-pin allowlist alongside `law.cornell.edu` (verified via the myflorida.com domain directory) — without this a correctly-fetched FL county surtax rate would render as an unpinned/non-authoritative source forever. The one real computation a no-income-tax state needs is on the FEDERAL side: `compute_sales_tax_deduction(table_amount, state_rate, local_rate, big_ticket_tax)` (new in `tax_computations.py`, strict bool/NaN/Infinity/negative rejection, `state_rate` must be `> 0`) implements the IRS Schedule A Optional State Sales Tax Tables method — `total = table_amount + table_amount*(local_rate/state_rate) + big_ticket_tax` — and its `total` is the INPUT to the *existing* `compute_schedule_a`'s `state_local_sales_taxes` parameter, so the income-vs-sales election and the SALT cap (`federal.salt_cap`, OBBBA-aware) are computed there, not duplicated; `/tax-compute` step 10 gained the no-income-tax branch (WebSearch the IRS optional-table amount, shell out to `compute_sales_tax_deduction`, write `florida_state.sales_tax_deduction` AND thread `total` into the Schedule A call) and `/tax-setup`'s state-law fetch step now special-cases `type: "none"` states — no income-bracket WebSearch (there is none to find), fetch only the county discretionary sales-surtax rate via a `site:floridarevenue.com` query, pin it under `_sources["state.FL"]`. `loss_harvest.py` gained `state_no_income_tax(tax_law)` (True only on an explicit `state.type == "none"` — absent/unknown type stays False, so an unfetched cache keeps the honest "not modeled" warning rather than silently reading as "no tax," the bias-direction rule applied to a brand-new signal) threaded onto `HarvestReport.state_no_income_tax` (default `False`, so old scenario JSON without the field still round-trips) AND into `_report_to_dict` for JSON serialization (a Codex-shaped miss the plan caught before review: computing the flag but never persisting it would silently regress on any reload) — `render_markdown` now branches three ways on the state-savings line (`state_modeled` / `state_no_income_tax` / neither) so a FL harvest shows "$0 — correct and complete" instead of the old blanket "not modeled, run /tax-setup" banner that misread a right answer as a gap. Registrations: `projection.STATE_SECTION_KEYS` and `yoy_diff.OPTIONAL_SECTIONS` both gained `florida_state` (appear/disappear tracking on a move year, for free, from the existing generic section machinery); `capabilities.py` gained `_NO_INCOME_TAX_STATES = frozenset({"AK","FL","NV","SD","TX","WY"})` feeding a new branch in `_state_note` that renders the affirmative "no individual income tax — no state return exists or is required" note instead of the generic "bracket-based ESTIMATE" text — WA and NH are DELIBERATELY excluded from this set (WA's capital-gains excise and NH's interest-and-dividends transition are not "no tax," and a blanket note there would be a false promise; they keep the estimate note until their own modules land, per the roadmap's Epic 2 follow-on). `tax_calendar.py` added a `state_property` category (`_VALID_CATEGORIES`/`Category` literal) and `events_fl_property(tax_year, business_tpp, new_homestead)` emitting the DR-501 homestead exemption (Mar 1, F.S. 196.011, gated on user-asserted `flags.fl_new_homestead`, first-year-only — renewals are automatic in most counties) and DR-405 tangible personal property return (Apr 1, F.S. 193.062, gated on `flags.has_business_tangible_property`, timely filing required to claim the $25,000 F.S. 196.183 exemption, 5%/month-to-25% late penalty) — both roll past weekends only via the existing `_state_due` convention (no county-holiday calendars modeled) and follow RESIDENCE (`address.state == "FL"`) which is the OPPOSITE gating direction from the PTET events below them in `build_events` (entity state, not resident state) — PRODID bumped v4→v5 to record the new category. `result_template.json` gained a `florida_state` section (`_include_if: "state is FL"`, informational only — `no_income_tax_statement`, `state_return_required: false`, the `sales_tax_deduction` sub-block, `use_tax_note`; explicitly NO computed-evidence pair, documented as a non-goal in the spec since there is no computed state tax for scaffold-vs-computed gating to protect) plus `_note_ca_savings`/`_note_california_refund` scaffolding comments marking the two remaining CA-branded leaks (`ira_contribution.ca_savings`, `balance_due_summary.california_refund`) as CA-only fields `/tax-setup` prunes for non-CA taxpayers, matching the new FL-specific pruning instruction added to `/tax-setup`'s interview section. `/tax-generate` step 4's state-return check now branches on `tax_law.state.type` (`"none"` → render the affirmative statement block, federal-only PDF header/subject, instead of the old unconditional CA-branded "California Full-Year Resident" rendering); `/tax-parse`'s missing-Box-17 cross-check flags ONLY when `state.type != "none"` (FL/TX W-2s normally carry empty Boxes 15-17 — flagging that as "missing" was a false positive) and now also flags nonresident-filing exposure when Box 15 names a different income-tax state than residence. `/tax-review` gained step 3.7 ("No-income-tax state completeness") plus its report-template embed slot (the same wiring pattern as the existing PTET step 3.6/embed) — checks the affirmative statement exists, the sales-tax election was actually taken when itemizing, the DR-15MO use-tax self-reporting note is surfaced, and (the EA-lens item with the highest dollar stakes) that FL residence does NOT remove nonresident filing obligations on other states' source income — with no FL resident return there is no credit mechanism, so another state's tax on an FL resident's income is a pure cost, plus the NY→FL domicile-audit checklist (Declaration of Domicile F.S. 222.17, DR-501 vs retained NY STAR as a disqualifying/audit-bait combination, the 184-day/>10-month statutory-residency tests). Finally, `docs/contributing/state-module-playbook.md` gained a "Variant: no-income-tax states (`type: "none"`)" section codifying FL as the worked example for the next `type: "none"` state, and a new `docs/superpowers/specs/2026-08-01-fl-state-module-design.md` records the playbook questionnaire answers and explicit non-goals (no `tie_out.CATEGORY_TARGETS` entry — no FL withholding exists; no `withholding.py` state block; no `/tax-extend` mechanics; no part-year/nonresident modeling, gated at the existing C1 `moved_states_this_year` capability rule instead). Suite grew 1891→1925 (+34 tests: template shape, freshness both directions, sales-tax math + validator rejections, harvest banner both directions plus JSON round-trip, capability note, calendar event gating/dates/weekend-rollover/UID stability, registration literals); `python3 agents/lib/tax_computations.py` self-test passes with the new sales-tax block appended.
